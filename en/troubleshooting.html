Help

Troubleshooting

Last updated: September 27, 2026

Something wrong? Here are the most common Vio and Studio problems and how to fix them in a few steps. If yours isn't here, type /doctor in the terminal: it checks models, network and settings and tells you what to fix.

First of all: update

Many problems are already fixed in the latest version. In the terminal type /update. In Studio, when there is something new, Vio shows you the Update button (or type /update in the chat). Your models and settings stay.

Vio

"No files changed: the agent did not apply any changes"

Vio answered but didn't write any file. Try these, in order:

  • Update MyDevAgent. Until September 27, 2026, with Ollama, long requests were cut off and Vio no longer saw what you asked. It happened mostly in Studio.
  • Type /context: if the bar is almost full, type /compact to summarize the conversation, or /clear to start over.
  • Be precise and name the file: "create index.html with…" works better than "make me a website".
  • Check the permissions: in plan mode Vio reads and proposes, but doesn't change anything. Press Shift+Tab to switch.
  • Small models (3B or less) sometimes don't use tools well: if your graphics card allows it, use a bigger profile.
"I can't reach the model server" / "Ollama is not responding"

Ollama is the program that runs the models on your PC. Open it from the Start menu (on a Mac from Applications), or run ollama serve in another terminal. Then try again. In Studio there's the Start Ollama button.

"The model … is not installed"

Download it with /pull model-name (for example /pull qwen2.5-coder:7b). In Studio just press Download the models. /models shows the ones you already have.

Vio is very slow, or "the model is too slow for this PC"
  • Use /fast for simple requests: one agent works instead of a team.
  • Pick a profile that fits your graphics card: cpu if you don't have one, gpu8 for 8 GB, and so on.
  • Close heavy programs (games, other models): Vio needs the graphics card's memory.
"The model does not fit in memory"

The model is too big for your RAM or graphics card. Close other programs, or use a smaller profile (mydevagent -p cpu or -p gpu8).

I moved or renamed the MyDevAgent folder and it no longer starts

Start it with run.bat: it notices the folder changed and repairs itself. If that's not enough, delete the .venv folder inside MyDevAgent and run run.bat again: it reinstalls everything (once).

/update doesn't work
  • "not a git copy": you downloaded MyDevAgent as a zip. Follow "Updating" in the README to connect it to GitHub, or download it again with git.
  • "you have local changes": you changed files inside the MyDevAgent folder. Run git stash in that folder and try again.
  • "GitHub is not responding": check your connection and try again in a bit.

MyDevAgent Studio

"I can't find MyDevAgent"

Studio looks for MyDevAgent on the Desktop, in Documents and in your user folder. If you put it somewhere else, press I already have it: choose the folder and pick the one with .venv inside. If you don't have it yet, press Install MyDevAgent: it downloads Python, Ollama, MyDevAgent and the models.

It works in the terminal but not in Studio

At startup Vio writes in the chat which MyDevAgent it is using (folder and version). If it's a different copy from the one you use in the terminal, pick the right one with the MyDevAgent: Path setting, or update that copy with the Update button.

Vio says "this folder is not trusted yet"

Studio opens new folders in restricted mode: until you trust it, Vio doesn't read, change or run anything. Press I trust this folder if the project is yours or comes from someone you trust.

"MyDevAgent closed"

Press Restart. If it happens again, press Show the log: the last lines say what happened. Often updating MyDevAgent or starting Ollama is enough.

Didn't find the fix? Open an issue on GitHub with a screenshot and the output of /doctor.
